## 第 9 轮：面向「部署给别人用」的数据加固

用户提出「要部署供其他人使用，数据也要安全完整全面」。先做了审计，结论：文本侧零 XSS 风险
（`el()` 全部走 `textContent`，只有一处硬编码 `innerHTML`），全站零外链（无 CDN / 字体 / 统计），
但存在三类真实问题，已逐条修掉：

- **缓存版本错配**（部署后最难查）：`index.html` 的 13 个资源标签统一加 `?v=20261029a`
  （1 css + 12 js）；`tools/check_enums.py` 新增第 7 节 `check_assets()`：版本串必须全部存在且完全相同、
  引用文件必须在磁盘上、`tests/app.smoke.js` 的 FILES 必须与 index.html 顺序一致。负向验证过（改一个版本串 → 报错）。
- **存档静默丢失**：`saveNow()` 写主键前先把盘上这版挪到 `is6calc.v1.bak`；`load()` 主键解析失败时
  回退备份（`readStored()` / `clearState()` 抽出）；`QuotaExceededError` / 无痕模式不再被 `catch(e){}` 吞掉，
  改为 `warnWrite()` 提示一次；`storage` 事件监听跨标签页写入并提示「本页再改会覆盖它」。
  `btnReset` / `showImport` 改成尊重 `saveNow()` 返回值，不再用「已清空 / 已导入」盖掉失败提示。
- **外链头像**：`core/repos/squads.repo.js` 加 `safeAvatar()` 白名单，只放行 `data:image/` 与本站相对路径
  （`assets/` `img/` `./`），拒绝 `http(s)://`、`//`、`javascript:`、超长串。
- **白屏**：`js/app.js` 顶层 `DB.load` 包进 try/catch（`bootError`），`init()` 里 `renderFatal()` 画红色说明块
  （CSS `.fatal`），不再白屏。实测缺 `data/is6db.js` 时能正常显示原因。
- **数据可见**：「公式说明」底部新增 `renderDataMeta()`（`.data-meta`），列资源版本 / schema 版本 + 游戏版本 /
  数据指纹 / 构建时间 / 三张表行数 / 存档格式；`assetVersion()` 从 script 标签自身读 `?v=`，不在 JS 里另写一份。
  `DB.check()` 不通过时除了 console.warn 还 toast 一次。
- **部署配置**：新增 `deploy/` —— `_headers`（Netlify/CF Pages）、`vercel.json`、`nginx.conf.snippet`，
  统一「入口不缓存 + 带版本串资源 immutable + 严格 CSP（default-src 'self'、connect-src 'none'）+ gzip」。
  CSP 只在响应头里给，不写进 index.html 的 meta —— file:// 下 `'self'` 是 opaque origin，会把脚本全拦掉。
- **二创声明**：帮助弹窗加「与鹰角网络无关、不收集个人信息」。
- 测试：smoke 141 → **153 项**（头像白名单 6 / 备份回退 3 / 写失败 2 / 数据版本块 1），
  用「再跑一遍 `doc._ready`」模拟刷新来测回退。全量：engine 205 / db 117 / smoke 153 / check_enums 0 / audit_relics 0。
- 浏览器实测：file:// 与 http://（python http.server + ?v= 查询串）都能正常启动；缺产物时兜底页可读。

## 第 10 轮：现状缺口盘点（用户问「还差什么，具体的」）

实测确认的缺口，按性质分：

**结构性问题**
- `core/db/db.js:161` 的 `_replace()` 是死代码（定义 + 导出，零调用）。
- 用户表在运行时**永远是空 Table**：`DB.table('squads')` 全库零调用，存档仍走
  `migrate.js` 的纯对象转换。表结构目前只承担「产物」和「存档格式定义」，没真正进运行时。

**发布硬缺口**
- 不是 git 仓库（无版本控制，改坏不能回滚）；无 `LICENSE` / `.gitignore`。
- 整目录 35 MB，其中 `raw/` 33 MB —— 整包上传会把官方原始表、`review/`（136 K 内部评审）、
  `tools/`、`tests/` 一起公开暴露。
- 无 favicon、无 `meta description`、无 og 标签（分享链接没有预览卡片）；无 `robots.txt` / `404.html`。
- `?v=` 手工维护，无 release 脚本自动 bump + 跑校验。

**体验缺口**
- 无 `keydown` 监听：弹窗不能用 Esc 关。
- 全站只有 4 个 `aria-` 属性；网格选人、槽位条、步进器都缺可访问名。
- 无 manifest.json / service worker（不能离线、不能加主屏）。
- 无「分享链接」（把配置编码进 URL），只有导出文件。
- 95%（238/251）藏品只有 1 档 → 藏品卡的「档位」下拉对绝大多数是摆设。

**数据缺口**
- 452 干员 avatar 全为空（0 个），网格只能用职业色块。
- 37 件藏品不可量化（已知）；`audit_numbers.py` 仍有 18 处数字未对上（时长/半径/概率）。
- 数据快照 2026-10-28，`raw/` 未核对是否最新。

**已验证不是问题**（避免误报）：390px 真实视口下顶栏会自动换行成 2×2，分类 chip 也换行，
没有横向溢出。唯一问题是首屏被藏品库占满、编队要往下滚 —— 优先级问题，不是 bug。
（注意：`--window-size=390` 会被 Edge 钳到 ~495px，测真机宽度要用 iframe 包一层。）
