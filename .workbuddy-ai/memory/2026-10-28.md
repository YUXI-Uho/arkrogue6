### 代码审查发现（待修）

1. **`spCost` 悬空（确认为 bug）**：`js/engine.js` 的 `PANEL_KEYS` 含 `spCost`，但 `computeOperator`
   没有对应结算分支 → 159 支柱-勤奋(-40%)、167 开拓之手(-50%) 这两条修正项进了 `acc.spCost.list`，
   在「加成明细」里显示为**已生效**，却对 `final` 无任何影响；`RESULT_ROWS` / `PANEL_FIELDS` 也没有 spCost 行。
   汇总区（`summarize` 动态建 key）反而会显示「技力消耗 -40%」，两边不一致。
   根因：干员数据表本身没有技能技力消耗字段，无法落到面板。
2. `acc[m.stat] &&` 的写法会把「不在 PANEL_KEYS 的 stat」静默丢弃，既不进面板也不进 special 清单。
   当前数据里没有这种 stat（已全量核查），但生成脚本一旦新增就会静默消失。
3. `final.interval` 用 `100 + (final.aspd - 100)` 隐式假定基础攻速恒为 100。目前数据里干员没有 aspd 字段
   （`app.js` 默认 100），所以没出错；补上真实基础攻速后会算错，应改成 `final.aspd / aspdB` 比例。
4. `STACK_PER_LAYER` 硬编码藏品 id（193/197/208/218），数据重生成后 id 变动即静默失效。
5. `parseRelic` 文案补漏去重键只按 `stat+pct`，忽略 scope：官方「全体 atk+10%」会挡掉文案里
   「近卫 atk+25%」这类更窄但更高的条目。
6. 取整口径不统一：hp/atk/def 用 floor，res/block 用 round，README 只声明了 floor。
