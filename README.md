# 明日方舟 · 集成战略「沉沦者的黑流树海」数值计算器

纯前端离线小工具：勾选手上的藏品，立刻看到**单个干员的最终面板**（含每件藏品的贡献明细）和**全队 / 探索加成汇总**。

双击 `index.html` 即可使用，数据已内置，不需要联网、不需要装环境、不需要构建。

---

## 用法

1. 双击 `index.html`（Chrome / Edge 均可）。

**界面分三页**，顶部页签切换，右侧不再把所有模块堆成一条长滚动条：

| 页签 | 内容 | 角标含义 |
| --- | --- | --- |
| **编队** | 12 格槽位条、添加干员、常用编队、干员卡（面板 / 结果 / 明细） | 已选人数 `n/12` |
| **汇总** | 伤害估算、面板加成、战斗加成、探索资源、特殊效果、未计入面板、解析统计、编队面板对照 | 当前生效的加成项数 |
| **战斗状态** | 时间 / 生命 / 资源 / 站位 / 状态开关 / 场上职业人数、条件类加成现状 | 与默认值不同的参数个数 |

页签右侧常驻「藏品 N 件 · 编队 n/12」，不切页也知道全局状态；停留在哪一页会被记住。
左栏藏品库可以点标题右侧的 `«` 收成一条窄带，把宽度让给编队网格（收起后能排 3 列干员卡）。

2. **选藏品**：左栏搜索 + 筛选。**点整张卡片选中，再点一次取消**；带四段成长（结构化 / 半结构化 / 非结构化 / 混沌化）的选了之后会出现「档位」下拉；按层累加的藏品会出现层数输入。
3. **加干员**：编队页顶部是一条 **12 格槽位条**，空位就是入口 ——
   - **点空槽位**直接展开全干员网格（452 名，全部可见），并自动聚焦搜索框
   - **点已占用的槽位**滚到对应的干员卡并闪一下；槽位右上角的 `×` 直接移出
   - 槽位左边一条颜色条是职业色，一眼能看出这队缺哪个职业
   - 网格里**点一下加入编队、再点一下移出**，已入队的卡片有高亮和勾选角标
   - 顶部实时显示 `已选 n/12`，**满 12 人后**未选卡片置灰并提示（与官方编队上限对齐）
   - 可按职业（八个按钮）、星级、名字筛选；同名干员不允许重复添加
   - 也可以点「空白干员」手填面板（可加多个，自动递增命名）
   - 内置 452 名干员的**精英化满级**面板，可勾「满信赖」
   - 每张干员卡右上角有「**详情**」：三档精英化面板、技能（类型 / SP / 持续 / 专三文案 / 攻击范围）、天赋、模组（三档属性增量 + 效果）、攻击范围方格、潜能。点某一档的「用此面板」会把该档面板填进编队，想算 E1 或 E0 的干员不用手抄数值
4. **常用编队**：默认折叠成一行，点开后可保存 / 载入 / 覆盖 / 删除。保存的是干员 + 面板 + 信赖 + 指定标记，不含藏品（藏品是当局的）。
5. 看每个干员卡里的「基础 → 最终 → 变化」，点「加成明细」能看到三组信息：
   - **已生效**：每件藏品给了多少、作用域是谁
   - **条件未满足 / 未生效**：被战斗状态挡住的项（划线显示，不计入）
   - **未计入面板**：数值上无法落到面板的属性（如技能技力消耗），会说明原因

   卡片顶部的「面板 / 分支 / 选项」是折叠的（空白干员除外，它需要填）。勾「只看变化」后结果表只保留有变化的属性行，12 张卡也能一屏扫完；「展开面板」可批量展开全部卡片。
6. **汇总页**：每张卡按「属性 + 作用域」聚合，**点任意一行展开来源**，看这条合计由哪几件藏品贡献；页面底部的「编队面板对照」把全队六项关键面板横向摊开（最终值 + 变化量），不用一张张卡翻。
7. **伤害估算**：攻击力可以直接从「用编队干员的面板…」下拉里选人填入（取该干员的最终攻击力），公式收在右上角的「公式」里。
8. 「战斗状态」页的参数会影响条件类藏品：
   - 每个分组标题后面标「影响 N 条」，说明这格到底有没有藏品在读
   - 场上职业人数是 **`−` 值 `+`** 步进器（0 ~ 12），不用手打数字
   - 勾上「触发类效果生效」才会计算「击倒敌人时」这类瞬时触发
   - 页面底部先给「N 项加成生效 / M 项因条件未满足而未生效」，再用两行一条的清单列出**条件类加成现状**（`●` 生效 / `○` 未生效，第二行写卡在什么条件上）

配置（藏品、编队、预设、战斗状态）自动存在浏览器本地（200ms 防抖），可用「导出 / 导入」搬。导入时会逐条校验，坏数据被丢弃并提示，不会白屏。

9. **分享链接**：点顶栏「分享」，当前配置会被压进链接的 `#cfg=` 里并复制到剪贴板，别人打开就是同一套编队。12 人满编的链接约 1.9 KB（如果直接编码存档会到 14 KB，聊天软件会截断，所以另做了一套紧凑格式）。打开带 `#cfg=` 的链接后会自动清掉 hash，避免你后续改动被链接里的旧配置覆盖。

配置写坏或浏览器存储满时会明确提示，不会静默丢；主存档读不出来会自动回退到上一次的备份。

## 计算口径

```
生命 / 攻击力 / 防御力 = floor( (基础值 + Σ固定加成) × (1 + Σ百分比加成) )
```

各属性的取整方式并不相同，与游戏内一致：

| 属性 | 处理方式 |
| --- | --- |
| 生命 / 攻击力 / 防御力 | `floor((基础 + Σ固定) × (1 + Σ百分比))` |
| 部署费用 / 再部署时间 | 同上，向下取整 |
| 法术抗性 | 基础 + Σ固定 + round(基础 × Σ百分比)，夹在 0–100 |
| 阻挡数 / 攻击速度 | 基础 + Σ固定 + 基础 × Σ百分比，四舍五入 |
| 技力回复 | 保留 2 位小数 |
| 初始技力 | 只累加固定值 |
| 攻击间隔 | 基础攻击间隔 × 100 ÷ 最终攻速（攻速以 100 为基准；分母 ≤ 0 时记 0） |

- 基础值 = 精英化满级面板（**不含潜能**），可叠加满信赖；
- 条件不满足的加成不计入，但会在明细里划线显示，汇总区也会提示「另有 N 项条件未满足」；
- 敌方减益（`敌人攻击力 -50%` 这类）不会算进干员面板，只出现在「战斗类加成」里。

## 跨藏品前置

有些藏品要同时持有另一件才生效（「拥有【断杖-同调】时…」）。这类写成 `hasRelic` 条件，
引擎在 `buildModifiers` 时把「本次选中的藏品集合 + 各自层数」挂到每条修正项上，所以：

- 没带前置 → 该条在明细里显示为「不生效（未持有）」，不会静默消失；
- 层数类还能跨藏品读：209 猎印的「每层【探测先锋】+10 法抗」直接读你给 142 填的层数。

已建模：167/168/169/170/171（对应 160/161/162/163/164）。

## 伤害估算

「汇总」页顶部有一张伤害估算卡，按官方公式结算，藏品里的伤害类加成都参与：

```
物理 = max(攻击力×倍率 − 有效防御, 攻击力×倍率×5%) × (1 + 造成伤害% + 脆弱% + 物伤易伤%)
法术 = max(攻击力×倍率×(1 − 法抗/100), 攻击力×倍率×5%) × (1 + 造成伤害% + 脆弱% + 法伤易伤%)
真实 = 攻击力×倍率 × (1 + 造成伤害% + 脆弱% + 真伤易伤%)
有效防御 = 敌方防御 × (1 − 无视防御%)
```

- 输入：攻击力（可直接填干员卡的最终攻击力）、技能倍率、敌方防御、敌方法抗；
- 「无视防御」目前来自 178 残弩-新典训（50%），只在伤害估算里生效，不进面板；
- 参与计算的藏品：`敌人受到物理/法术/真实伤害`、`造成伤害提升`、`易伤(脆弱)`、`无视防御`；
- 卡片下方会列出实际参与的组合，方便对照（例如「防御 200（无视 50% → 100）」）。

## 数据层：自己的表

页面是纯静态的（`file://` 直接打开、没有构建步骤），所以「数据库」不是 SQL 引擎，而是
**一份表结构定义 + 一份表产物 + 一个查询器**，全部跑在内存里：

```
core/db/schema.js   ← 表结构唯一事实来源（DDL）
        │
        ├── tools/build_db.py   按同一份列定义把 JSON 装配成表
        │        └── data/is6db.js   { meta, tables }（1550 KB）
        │
        └── core/db/db.js       装载 → Table（主键 O(1)、二级索引懒建、条件筛）
                 │
                 ├── core/db/migrate.js   存档 v2 ↔ v3（四张用户表）
                 └── core/repos/*.repo.js 业务形状（界面只认仓储）
```

### 十三张表

| 表 | 类型 | 主键 | 行数 | 说明 |
| --- | --- | --- | --- | --- |
| `relics` | 只读 | `id` | 251 | 藏品本体（名称/分类/稀有度/图标/描述/档位数） |
| `relic_stages` | 只读 | `relicId` + `stage` | 290 | 每件藏品的每一档（文案 + `mods` 结构化修正项） |
| `operators` | 只读 | `id` | 452 | 干员面板，`panel` 拍平成 `hp/atk/def/res/…` 列 + 特性/标签/潜能/范围 |
| `operator_phases` | 只读 | `id` + `elite` | 1303 | 精英化零/一/二各满级一帧（面板成长曲线） |
| `operator_skills` | 只读 | `id` + `slot` | 997 | 技能：类型 / SP / 持续 / 专三文案 / 范围 |
| `operator_talents` | 只读 | `id` + `idx` | 615 | 天赋：名称 / 文案 / 解锁阶段 |
| `operator_modules` | 只读 | `id` + `moduleId` | 901 | 模组：名称 / 类型 / 解锁条件 |
| `operator_module_levels` | 只读 | `id` + `moduleId` + `level` | 1524 | 模组三档的属性加成与效果文案 |
| `ranges` | 只读 | `id` | 55 | 攻击范围格子坐标 `[[row, col], …]` |
| `selection` | 读写 | `relicId` | 用户 | 已选藏品 + 当前档位 + 层数 |
| `squads` | 读写 | `id` | 用户 | 编队，`ord` 列保序（表本身无序） |
| `presets` | 读写 | `name` | 用户 | 常用编队 |
| `settings` | 读写 | `key` | 用户 | 战斗状态 / 伤害估算输入，一行一个参数 |

九张 `game` 表随官方数据整体重建；四张 `user` 表只存在于浏览器本地，不进产物。
**只有 user 表参与存档**，所以增删 game 表不影响存档格式，不用升版本号。

几个刻意的决定：

- **`relic_stages` 单独一张表**：四段成长（结构化 / 半结构化 / 非结构化 / 混沌化）本质是一对多，
  塞进 `relics.stages[]` 里就没法按档位查，也没法对单档做 diff。
- **`squads.ord`**：表是无序集合，没有这一列就还原不出玩家排的队伍顺序。
- **`settings` 一行一个参数**：以后加战斗状态不用改表结构，也不用改读取侧的判断。
- **`operators` 拍平**：`panel` 嵌套对象拆成独立列，列名与 `core/schema.js` 的 `PANEL_FIELDS`
  一一对应，加面板字段时两处一起改（`check_enums.py` 会查）。
- **干员详情拆成五张表**：阶段 / 技能 / 天赋 / 模组 / 模组档位都是「一名干员多行」，
  塞进 `operators` 的 JSON 列就只能整块读，没法按 `elite`、按 `slot`、按 `level` 查，
  也没法在装配期校验主键唯一。拆开之后每张表的主键都是 `(干员, 序号)`，重复直接报出来。
- **模组档位的 `desc` 会留空**：与上一档文案相同时不重复写，读取侧回退到最近的非空档
  （`OperatorRepo.modulesOf` 返回的已经是补全后的行）。三档文案完全相同的模组有 508 个，
  不这么做产物要多 150 KB。

### 版本与更新

`DBSchema.VERSION`（当前 3）同时是**表结构版本**和**存档版本**，`DBMigrate.VERSION`、
`SquadRepo.SCHEMA_VERSION` 都直接引用它，不存在两处各写一个号的情况。

- 产物版本 **高于** 代码：`DB.load()` 直接抛错，宁可启动失败也不用旧代码读新字段。
- 产物版本 **低于** 代码：记一条 issue，界面照常打开，控制台提示「请重新生成」。
- 启动时 `DB.check()` 拿行数与产物 `meta.counts` 对账，生成器算错或文件被截断能立刻发现。

官方版本更新后一条命令重建：

```powershell
python tools/update_db.py            # 抓→装表→校验，四步
python tools/update_db.py --test     # 额外跑三套测试
python tools/update_db.py --skip-build   # 只用现有 JSON 重装表
```

产物 `meta` 里带 `gameVersion`、`builtAt`、`dataHash`（`sha256:` + 16 位）和 `counts`；
每次重装都会把「新增/删除/数值变化」追加到 `data/DB_CHANGELOG.md`，便于对照官方改动。

**存档迁移**：写出去永远是 v3 表结构，读的时候 v2（`{squad:[...], relics:{...}}`，含裸数组）
和 v3 都认。旧存档打开一次就自动升级，提示一句「已把旧存档升级为表结构 v3」，数据不丢。

## 数据从哪来（重点）

藏品效果**不是靠读中文文案猜的**，而是直接读游戏数据表里每件藏品的结构化 buff：

```
raw/roguelike_topic_table.json  →  details.rogue_6.relics[relicId].buffs[].blackboard
```

例如「折戟-锋刃」在游戏数据里就是：

```json
{"key": "char_attribute_mul",
 "blackboard": [{"key": "selector.profession", "valueStr": "warrior"},
                {"key": "atk", "value": 0.25}]}
```

→ 近卫 攻击力 +25%。属性字段（`atk` / `def` / `max_hp` / `attack_speed` / `cost` / `magic_resistance` /
`block_cnt` / `respawn_time` / `sp_recovery_per_sec` …）、作用域（职业 / 分支 / 近战远程 / 敌方）、
层数来源（每 5 源石锭、每场战斗…）、奖励 id（希望 / 可携带干员 / 护盾…）全部来自数据，
转换规则是 `tools/build_relics_official.py` 里一张写死的表（`convert_buff` / `named_rule`），可查可改。

四段成长在数据里是同一件藏品的 `_a` / `_b` / `_c` 变体，工具会自动拆成 4 个阶段。

**覆盖情况**（251 件，按「结构化」阶段统计）：

| 来源 | 数量 | 说明 |
| --- | --- | --- |
| 官方结构化 | 198 件 | 全部修正项都来自 buffs |
| 官方 + 文案补 | 9 件 | 官方覆盖了大部分，文案补上未覆盖的属性（费用类不补，见下） |
| 文案解析兜底 | 7 件 | 官方 buff 是行为类（召唤、浮空、弹药等），退回中文规则解析 |
| 仅特殊效果 | 37 件 | 招募 / 掉落 / 节点 / 结局条件、战术道具等，不改变任何数值 |

合计 214 件可量化、327 条修正项（「结构化」阶段口径；四段合计 389 条）。列表里每件藏品会标「官方结构化」或「文案解析」；解析不出数值的标「特殊/未量化」，汇总区也能看到本次选中的来源分布。

## 已知限制

- 不含潜能、不含技能倍率（算的是「藏品 + 面板」静态结果，主动技能请自行叠加）。
- **技能数据只用于展示，不参与计算**：`operator_skills` 里已经有技能类型、SP 消耗、持续、
  专三文案和攻击范围，点编队卡上的「详情」能看到；但结算引擎仍然只吃面板，
  技能倍率 / 持续时间没有接进伤害估算。相关藏品（如「支柱-勤奋」「开拓之手」）会出现在
  干员的「未计入面板」清单里并说明原因，不会假装生效。
- **「用此面板」只替换面板**：详情页可以把 E0 / E1 / E2 任意一档填进编队，
  但编队条目不会记住「这是 E1」，重新打开后仍按存档里的具体数值算 —— 这是有意的，
  玩家手改过的面板和官方面板在数据里长得一样，多存一个 `elite` 字段反而会产生两种真相。
- **模组只展示属性加成，不参与计算**：`operator_module_levels` 里有三档的 hp/atk/def 增量，
  但没有「玩家装了哪个模组」这个状态，所以不会自动加到面板上。
- 「场上职业人数」用 `−` / `+` 步进器调（0 ~ 12），或点「按编队填充」一键按当前编队统计。
- 「下一个招募/进阶的干员」类一次性藏品，只对勾了「一次性藏品指定此人」的干员生效。
- 少数行为类藏品（浮空、弹药、距离增伤）不进面板，但会出现在「特殊效果」清单里，不会被静默丢掉。
- 加成主语是具名单位（敌方单位、召唤物，如「猎犬proto」）的文案不会套用「全体我方」，而是进「特殊效果」——宁可不算，也不会错算。
- 层数上限对少数藏品是从文案「最多 N 层」推断的，官方数据里没有显式字段。
- 「初始部署费用」（人偶之家 / 微缩舞台模型 / 缠梦古堡模型）是**局内开局的部署费用**，只进「探索 / 运营」，不改变任何干员的部署费用；「开启技能获得部署费用」（钝爪-先机）同理，是回费而非涨价。
- 官方 selector 常常写成「八个职业全选」，实际范围由文案收在「地面 / 高台」上；这类藏品会用文案把作用域收紧到近战位 / 远程位（114、113、119、214 等）。
- **没有干员立绘**：仓库里没有头像资源（452 名干员的 `avatar` 全为空），网格里用「职业简称 + 职业色」的色块代替。要上真实头像需要另找图源，并自行确认二次使用许可。
- **37 件藏品无法量化**：招募概率、掉落、节点、结局条件、战术道具这类行为效果，不进面板，只列在「特殊效果」里。
- `audit_numbers.py` 仍有 18 处文案数字没对上，全部是时长 / 半径 / 概率这类非面板属性，属于已知项。

## 部署给别人用

页面本身是纯静态的：没有构建步骤、没有外部资源（字体、CDN、统计脚本一个都没有），
整个仓库直接传上去就能跑，不需要后端。`server/` 里另有一套可选的 API，
复用同一份引擎与同一份表产物，只有想给别的程序调用时才需要部署。
「本地能开」和「上线能用」之间隔着五件事。

### 0. 一条命令发布

```powershell
python tools/release.py            # 版本串 +1 → 跑全部校验 → 生成上传清单
python tools/release.py --dry-run  # 只校验，不改 index.html
```

它做三件事：把 `index.html` 里 16 处 `?v=` 统一 +1（`20261029a → 20261029b`）、
依次跑 `build_db.py --check` / `check_enums.py` / 四套测试、最后生成 `deploy/FILES.txt`
（21 个文件 / 1.8 MB，附响应头说明）。任一步失败会**还原 index.html**，不会留下半成品。

`deploy/FILES.txt` 里那张表就是该传的东西 —— 刻意不含 `raw/`（52 MB 官方原始表）、
`tools/`、`tests/`、`review/`、`server/`。整包上传等于把抓取缓存和内部评审一起公开。

### 1. 缓存版本要一致

`index.html` 里 16 个资源标签（1 个样式表 + 12 个脚本 + 图标 + apple-touch-icon + manifest）
都带同一个 `?v=` 版本串。原因是部署后 CDN 和浏览器会把旧文件缓存住，**代码更新而
`data/is6db.js` 还是旧版**（或反过来）会是最难排查的故障：界面能开，数值却对不上。

发布前跑 `python tools/release.py` 会自动统一改；`python tools/check_enums.py` 会校验：

- 16 个标签是否都带了 `?v=`；
- 版本串是否**完全一致**（不一致 = 会新旧混跑）；
- 引用的文件是否都在磁盘上（漏传文件是部署第一大事故）；
- `tests/app.smoke.js` 的加载清单是否与 `index.html` 一致（否则测试通过、线上挂）。

### 2. 缓存头与安全头

`deploy/` 里备好了三份等价配置，按托管方式挑一份：

| 文件 | 用在哪 | 怎么用 |
| --- | --- | --- |
| `deploy/_headers` | Netlify、Cloudflare Pages | 放到站点根目录，文件名保持 `_headers` |
| `deploy/vercel.json` | Vercel | 放到仓库根目录 |
| `deploy/nginx.conf.snippet` | 自建 nginx | 粘进 `server { }` 块 |

策略是「入口不缓存 + 带版本串的资源长期缓存」，外加一组安全头。其中 CSP 可以上到最严
（`default-src 'self'`、`connect-src 'none'`），因为页面确实零内联脚本、零内联样式、零外链 ——
万一哪天混进一段注入代码，浏览器会直接拦掉。

> GitHub Pages 不能自定义响应头，`_headers` 不生效，CSP 也上不去。要安全头就换上面三种之一。

### 3. 压缩

`data/is6db.js` 有 1550 KB，gzip 后约 227 KB。托管平台默认开，自建服务器记得在 nginx 里
`gzip_types` 加上 `application/javascript`，否则首次加载会明显慢一拍。

### 4. 加载失败要说人话

产物缺失、路径对不上、缓存错版本时，`js/app.js` 不再白屏：`DB.load` 被包在 try/catch 里，
失败时在页面上画一块红色说明，写明原因和「先 Ctrl+F5 强刷，仍不行请反馈这行文字」。
「公式说明」弹窗底部还有一块**数据版本**，列出资源版本、schema 版本、数据指纹、构建时间、
三张表行数 —— 用户说「某个数值不对」时，让他把这块抄过来，就能确认双方看的是不是同一份数据。

### 用户数据放在哪

编队、藏品选择、常用编队、战斗状态只存在用户自己的浏览器里（单键 `is6calc.v1`，约 12 KB），
不上传、不收集、没有账号体系。为了不让这份唯一的数据丢掉，写入侧做了三件事：

- 写主键前先把盘上这一版挪到 `is6calc.v1.bak`，主键读不出来时自动回退备份并提示；
- 配额满 / 无痕模式导致写失败时明确弹提示（以前是 `catch` 完就静默吞掉）；
- 另一个标签页保存了新存档时提示「本页再改动会覆盖它」，被覆盖的版本仍在备份键里。

跨设备迁移靠「导出 / 导入」的 JSON，导出文件带 `schemaVersion`，旧格式导入会自动升级；
短配置也可以用「分享」按钮压进链接的 `#cfg=` 里。

## 可访问性与离线

- **键盘**：页签是 `role="tab"` + `aria-selected`，网格卡片是 `role="button"` + `aria-pressed`
  且可用 Tab 聚焦、Enter / 空格选中；`Esc` 关闭弹窗，关闭后焦点回到打开它的那个按钮。
- **读屏**：卡片带可访问名（「玛恩纳，近卫，6 星，领主，未在编队」），提示条是
  `role="status" aria-live="polite"`，弹窗是 `role="dialog" aria-modal="true"`。
- **离线**：`sw.js` 在 http(s) 下注册。导航请求**网络优先**（避免被 SW 锁在旧版本里），
  其余资源缓存优先；所有资源 URL 带 `?v=`，版本一变就是新 URL，不会串版本。
  `file://` 下不注册（浏览器不允许），双击打开时行为与以前一致。
- **主题**：目前只有深色。没有跟随系统切换。
