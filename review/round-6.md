## 一、本轮修掉的问题

### P1 175 断杖-新典训：术师法抗被「加」了 5 点（对象 + 方向 + 口径三重错）

文案「攻击时降低目标5点法术抗性」。官方已给出 `enemyRes = -5`，但文案补漏又解析出一条
`res = +5`，作用域还继承成「术师」。

三个独立的错叠在一起：

1. **作用域**：`detectScope` 走到「我方受益证据」兜底，继承了上一分句的 `【术师】`；
2. **方向**：数字在属性名前面（「5点法术抗性」），走 `before` 分支，`降低` 这个动词被丢掉了；
3. **口径**：敌方作用域只把 `hp/atk/def` 归一成 `enemy*`，漏了 `res`。

结果：每名术师白拿 5 点法抗，而官方那条正确的 `敌人法抗 -5` 还在旁边。

修复：

- `detectScope` 增加一条前置规则「降低/减少/削弱 + 目标/敌人/敌方 → 敌方」，排在「我方受益证据」之前；
- `matchStatGroup` 的 `before` 分支识别「数字前 8 字内有降低/减少/削弱」并取负；
  带动词的路径（「敌人防御力降低40%」）同样取负，但 `降低至` 走倍率分支、不取负；
- 敌方作用域补上 `res → enemyRes`。

### P1 181 支柱-新典训：多出一条面板口径的「法术抗性（对敌）-40%」

同一个 `res` 漏归一。官方 `enemyRes -40` 与文案 `res -40`（敌方作用域）各记一条，
后者因为 bucket 是 panel，被 `summarize` 的 enemyPanel 规则改投战斗卡，于是战斗卡里
「敌人法术抗性 -40%」出现两次。归一后两条按 `stat + pct` 去重，只剩一条。

### P1 134 河谷祭祈：四种元素损伤被加成 530%

官方 buff 按元素写了四条 `rogue_6_enemy_ep_break_fix[dark/fire/sanity/water]`，
`damage_scale` 分别 2.5 / 3.8 / 2.0。四种元素**互斥**（同一个敌人只吃自己那一种），
但汇总卡按 `属性 + 作用域` 求和，渲染成「元素伤害/损伤（对敌）+530%」。

修复方式是加一个通用字段 `group`（互斥分支标签），而不是为一件藏品造四个属性：

- 生成器：`ELEMENT_NAMES` 把 `[dark]/[fire]/[sanity]/[water]` 译成凋亡/灼燃/神经/侵蚀，
  `dedupe_mods` 的键加入 `group`；
- 引擎：`buildModifiers` / `computeOperator` / `summarize` 透传 `group`；
- 界面：汇总卡的三张卡片按 `属性·group` 分行，求和只在同组内发生。

现在显示为「元素伤害/损伤·凋亡 +150%」「·灼燃 +280%」「·神经 +100%」三行。

### P2 「敌人易伤(脆弱)（对敌）」措辞重复

`weak` 的 label 自带「敌人」，战斗卡又按作用域追加「（对敌）」。label 改为「易伤(脆弱)」，
对象由「（对敌）」表达。

### P2 `STAT_MAP['sp'] = ('sp', 'panel')` 与注册表冲突

`core/schema.js` 把 `sp` 登记在 run 桶，生成器却按 panel 发。当前数据没有命中（0 条），
属于「下次一命中就错桶」的哑雷。已删除该映射，`sp` 的语义统一由 `named_rule` 按
buff 命名分派到 `spOnAttack / spOnKill / spOnSkillEnd / initSp`。

### P2 生成器死代码

`specials` 自上一轮起恒为空（不再写 `[buff_key field=1.0]` 调试串），`describe()` 成了
死函数；模块 docstring 还写着「保留为 special，交给界面展示」。已删 `describe()`、
改正注释，`special` 字段保留（引擎侧兼容，未来可接可读描述）。

## 二、只记录、未改动的问题

1. **`computeOperator` 不处理 `bucket === 'enemy'`**：干员卡明细里，combat 桶的敌方项会出现
   （208 的「敌人生命 -40%」），enemy 桶的不会（181 的「敌人防御 -40%」）。两种桶在队伍汇总里
   是等价的，在单人明细里不等价。属于一致性问题，不是数值错误；改动会把所有对敌减益塞进
   每张干员卡，噪声上升，因此留待确认交互后再改。
2. **209 猎印的残句重复**：`guarded` 里保留「猎犬proto的攻击力-50%」用于解释「为什么不套用全体」，
   但官方 `enemyAtk -50` 已经把这条量化了，界面上会同时出现在「战斗类加成」和「特殊效果」。
   信息不矛盾，只是重复。
3. **「每 5 秒回复 1 点生命」不进数值**：解析器只认「每秒回复 N 点」，频率不是 1 秒时宁可
   进残句清单，也不折算成 0.2/秒（折算会引入小数误读）。当前数据里没有命中。
4. **37 件「无修正」是真实不可量化**：招募/掉落/节点/结局条件、支援道具（携带 1~3 个地雷等）、
   随机产出。这些不该被硬凑成数值。
