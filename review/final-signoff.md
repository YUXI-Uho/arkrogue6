### 3.2 发现的数据问题

**(a) 4 件藏品带 `+0` 假修正项（生成脚本 bug）**

| id | 名称 | 原始 buff | 被转成 |
| --- | --- | --- | --- |
| 224 | 追忆 | `immediate_reward id=rogue_6_hp count=0` | `targetHp 0` |
| 236 | 击坠"神明" | 同上 | `targetHp 0` |
| 237 | 湮没"光明" | 同上 | `targetHp 0` |
| 238 | 焚毁"文明" | 同上 | `targetHp 0` |

根因清楚：`build_relics_official.py` 的 `immediate_reward` 转换没有跳过 `count == 0`。后果有两个，都是用户可见的：

1. 这 4 件被 `parseRelic().mods.length > 0` 判为「可量化」→ 进「只看可计算」筛选、进 `195/251` 的分子；
2. 勾选它们，汇总区「探索 / 运营」会出现一行 **`目标生命（全体我方） +0`**，而且这 4 件**没有任何「特殊效果」兜底说明**（`special` 与 `unmatched` 都是空），用户会以为这就是全部信息。

实测（`summarize` 输出）：

```json
run: {"targetHp":{"flat":0,"items":[
  {"relicId":"224","relicName":"追忆","value":0,"ok":true},
  {"relicId":"236","relicName":"击坠“神明”","value":0,"ok":true}]}}
```

**(b) `bucket` 字段在数据侧与 schema 侧不一致（16 条）**

`data/relics.json` 的 `mods[].bucket` 与 `core/schema.js` 的声明有 16 条不同：

```
035 enemyHp/enemyAtk  data=combat  schema=enemy
073/074/075/076 enemyHp/enemyDef  data=combat  schema=enemy
065 weight  data=enemy  schema=combat
```

引擎的 `summarize()` 读的是 `m.bucket`（数据侧），不是 `S.bucketOf()`。影响仅限于「进哪张卡片」（`enemy` 桶在 UI 里没有独立卡片，会落到「战斗类加成（对敌）」），**不影响任何数值**。但 schema.js 头部宣称的「唯一事实来源」在这一列上没有兑现——数据里还藏着第二份 bucket。属于一致性债，不是交付阻塞。

**(c) 7 名干员没有 `subProfession`**

`Misery`、`Raidian`、`预备干员-先锋/医疗/特种/辅助/近卫`。后果：所有「分支限定」藏品（`scope.subProfs`）对这 7 人永远不生效。7/452，且都是新干员或预备干员，可接受，但应写进已知限制。
